# CityBrain final demonstration checklist

## Before the session

- Confirm Python dependencies, SUMO 1.27.1, TraCI bindings and a WebGL-capable browser are installed. Use the setup notes in [`docs/V3_SETUP.md`](../../docs/V3_SETUP.md).
- Start from the repository root. Keep the terminal visible so the local URL and final simulator status can be shown.
- Do not configure provider credentials or enable live requests. This demonstration uses simulation or saved synthetic replay only.
- For the full guided walkthrough, start the synthetic replay-assisted dashboard:

```sh
./tools/run_chennai.sh --mode replay-assisted --experimental-traffic-evaluation
```

The launcher prints the browser URL. With default settings it is `http://127.0.0.1:8770`. Open that local URL in the browser.

## What to show

1. **Evidence boundary:** say the roads are OSM-derived; vehicle movement, traffic, incidents, signals and hospital availability are simulated. Replay sample data is synthetic, not live Chennai traffic.
2. **Digital twin:** point out the map, moving SUMO vehicles, ambulance, current/accepted route, simulated incident and configured hospital. The refreshed submission screenshot is a current replay capture at 200 simulated seconds, with a recorded active ambulance. At 704 seconds, a terminal note explains that no active vehicle fix remains.
3. **Route lifecycle:** show the planner decision and accepted route. Explain that CityBrain applies the route through the existing executor and checks SUMO route read-back before logical acceptance.
4. **Stability guard:** explain that a soft route-cost change must remain confirmed for 20 seconds. A genuine hard invalidation retains immediate handling.
5. **Signals and traffic:** select a signal to show simulated phase/link telemetry. Signal suggestions are `ADVISORY_ONLY` and are not applied. Read the traffic provider/source and freshness labels aloud.
6. **Advisor:** if enabled, explain that it displays a candidate and evidence only. It cannot call the production planner, alter its scores or commit a route.
7. **Privacy and limitations:** browser location is consented and tab-local. A `SUCCESS` means reaching a configured simulated hospital access road, not clinical capacity or driveway verification.

## Source and freshness labels

- `SUMO_SIMULATED`: state generated by the SUMO simulation.
- `REPLAY` / `SYNTHETIC_SAMPLE`: an offline synthetic sample used to test the observation path; it is not a provider measurement.
- `LIVE`: reserved for a provider response received during an explicitly authorized request. No such response is part of this submission evidence.
- `UNKNOWN`: source time or another required quality property is unavailable. Do not describe unknown as fresh.
- `STALE` / `EXPIRED`: the observation is too old for current use; it may remain visible as historical context.
- `VERIFIED ROAD MATCH`: the observation passed the directed geometric road-matching checks. It does not prove provider coverage or real-world accuracy.

## If the 3D view fails

- Use the dashboard’s **2D / 3D** control to move to the SVG/2D view.
- If a completed local replay is available, start it read-only in another terminal:

```sh
./tools/run_chennai.sh --mode replay \
  --events /path/to/completed-chennai-output \
  --port 8773 --no-browser
```

- Open `http://127.0.0.1:8773`, use the replay timeline and inspect the route, vehicles, signals and provenance labels.
- If the temporary replay directory is missing, use the main replay-assisted command above, which creates a fresh local demonstration. Do not use the experiment runner or write into official research result directories.

## Safe shutdown

Press **Ctrl-C** in the terminal that owns the launcher and wait for its shutdown message. The launcher closes its TraCI connection and local server. Do not kill SUMO separately unless normal cleanup has failed.
